# Versioning Policy

The project follows Semantic Versioning.

Format

MAJOR.MINOR.PATCH

Example

1.0.0

---

## MAJOR

Changed when:

- breaking changes are introduced
- incompatible database changes are made
- major architectural redesign occurs

Examples

1.0 → 2.0

---

## MINOR

Changed when:

- new features are added
- existing functionality remains compatible

Examples

1.0 → 1.1

---

## PATCH

Changed when:

- bugs are fixed
- documentation is corrected
- performance improvements are made

Examples

1.0.0 → 1.0.1
